<span class="doc-status">🤖 AI policy</span>

ИИ должен воспринимать эту документацию как **версионируемую базу доказательств**, а не как разрешение додумывать отсутствующие детали API.

## Основные правила

1. Использовать записи **Verified** как подтверждённые факты только для указанных версий WorldBox / NeoModLoader.
2. Учитывать метки **Observed**, **Experimental** и **Inferred**.
3. Никогда не рекомендовать подход со статусом **Failed** как рабочее решение.
4. Если имя API, сигнатура метода, поле, lifecycle event или поведение не документированы — помечать их как **unverified**.
5. Предпочитать минимальный reflection/runtime probe выдумыванию правдоподобного API.
6. Не переводить имена WorldBox API, C# identifiers, текст логов и имена файлов.
7. В ответах разделять доказательство и вывод.

## Рекомендуемый ответ при неизвестном API

```text
Этот API не подтверждён текущей документацией.

Следующий шаг:
1. проверить нужный тип через reflection;
2. залогировать возможные members/signatures;
3. протестировать минимальный вариант в runtime;
4. записать результат и версии WorldBox/NML.
```

## Известный пример

ИИ, угадывающий по смыслу, мог бы принять `WorldTile.health` за подходящее числовое хранилище во время общего reflection-поиска.

TerraForge проверил этот путь и доказал, что для высоты рельефа он неверен.

Подтверждённый вариант для текущей базовой среды — `WorldTile.Height` / `WorldTile.data.height`.

## Базовая среда

- WorldBox 0.51.2 build 719
- NeoModLoader 1.2.0.1

Совместимость с будущими версиями нужно перепроверять, а не предполагать.
