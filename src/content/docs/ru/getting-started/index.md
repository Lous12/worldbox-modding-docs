# Начало

Тебе **не нужно** сначала учить весь API WorldBox. Самый безопасный путь новичка короткий: добиться, чтобы loader увидел мод, подтвердить загрузку через `Player.log`, а уже потом добавлять одну механику.

## 1. Убедись, что NeoModLoader работает

Запусти WorldBox с установленным NeoModLoader. Если у тебя уже есть `Player.log`, открой [Анализатор Player.log](../workbench/log-analyzer/). В нормальной NML-сессии из лога обычно можно вытащить версию NeoModLoader и строки загруженных модов.

Если NML вообще не появляется, пока не копируй API-код. Отдельную установочную инструкцию мы будем расширять по версиям только после проверки конкретных шагов.

## 2. Создай самый маленький мод

Открой [Генератор стартового мода](../workbench/mod-generator/). На текущем исследовательском стеке рабочие WBML probes используют папку мода минимум с такими файлами:

```text
MyMod/
├── mod.json
└── Main.cs
```

Генератор использует `BasicMod<Main>` и `OnModLoad()`, потому что такая структура реально компилировалась и загружалась в наших текущих WBML-экспериментах.

## 3. Запусти игру до добавления механик

Не добавляй сразу UI, Harmony patches, persistence, events и ещё десять систем. Сначала запусти игру и найди простое сообщение `Loaded` / `OnLoad` в `Player.log`.

Если что-то сломается, маленький мод разбирать намного проще.

## 4. Добавь одну механику

Хорошие первые варианты:

- [сохранить свои данные за kingdom](../guides/kingdom-custom-data/)
- [сделать addon для Political World](../guides/politicalworldapi-runtime-baseline/)
- [найти подтверждённый API по задаче](../workbench/api-explorer/)
- [открыть решение проблем](../troubleshooting/), если всё взорвалось

## 5. Проверяй границы доказательства

Код может быть правильным для одного сочетания WorldBox/NML/API и устареть позже. Перед использованием исследовательского поведения смотри [Матрицу совместимости](../workbench/compatibility/).

**Правило новичка:** сначала заставь мод загрузиться, потом заставь работать одну вещь, и только потом делай умно и сложно.
