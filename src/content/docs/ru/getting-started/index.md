# Начать здесь

Тебе **не нужно** сначала понимать весь API WorldBox. Первая задача намного меньше:

```text
NeoModLoader работает
        ↓
твой мод компилируется и загружается
        ↓
твой marker появляется в Player.log
        ↓
работает одна маленькая механика
        ↓
и только потом: большие системы
```

## До того как трогать код

На старте достаточно нескольких вещей:

- WorldBox, где NeoModLoader уже запускается;
- любой удобный редактор кода/текста;
- `Player.log`, потому что он показывает, дошли ли мы до compile/load/runtime;
- отдельный тестовый save, если рецепт меняет состояние мира.

Для первого успешного запуска тебе **не нужны** Harmony, свой UI, огромная архитектура, база данных или двадцать папок.

## Полезная привычка при отладке

Когда что-то не работает, называй **этап**, а не просто «мод сломан»:

```text
NML не видно
→ loader/setup

C# error / мод не компилируется
→ compile

мод загружен, но своего marker нет
→ load / entry-point assumption

marker есть, механика не работает
→ feature/runtime

сейчас работает, после reload/restart пропадает
→ persistence/lifecycle
```

Так намного проще найти причину, чем одновременно менять несколько несвязанных файлов.

## После первого успеха

Выбери **одну** цель в [Рецептах](../recipes/). Если рецепт зависит от version-sensitive поведения, открой [Матрицу совместимости](../workbench/compatibility/) и посмотри статус evidence, прежде чем считать поведение универсальным.
