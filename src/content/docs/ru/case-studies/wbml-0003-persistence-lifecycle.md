<span class="doc-status">WBML-0003</span>

Первый WBML-0003 показал важную ловушку: данные могут тестироваться правильно, а итоговая матрица — нет.

После полного restart старые counters жили только в памяти умершего процесса, поэтому финальный отчёт нового процесса уже не охватывал ранние фазы.

## Исправление

`0.0.3-fix1` сохранил вместе с данными:

```text
phase gates
PASS / FAIL / SKIP до restart
run marker
resume phase
```

После запуска нового процесса Lab сначала восстановил доказательную матрицу, а потом продолжил.

## Что это позволило доказать

Party-private int/string/bool/float вернулись после полного restart. У безопасной не правящей партии эти данные читались и во время inactive, а reactivate вернул active state.

## Урок новичку

Если эксперимент пересекает restart, проверяй две вещи:

1. пережили ли restart данные функции;
2. пережили ли restart доказательства предыдущих шагов.
