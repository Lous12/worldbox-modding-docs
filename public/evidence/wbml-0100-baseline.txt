# WBML 0.1.0 — First Research Baseline

This is the first consolidated research baseline after suites **0.0.1–0.0.30**.
It is a knowledge snapshot, not a request to rerun closed suites.

Baseline environment used for the strongest evidence:
- WorldBox **0.51.2**, build **719**
- NeoModLoader **1.2.0.1**
- Unity **2022.3.60f1**
- ResearchEngine **v2.1.1**
- Political World **1.7.0**, API **1.14.0**
- Cross-mod tests included Political World, Custom Worldsize and Scenario Tools

Classification policy:
- **VERIFIED** — supported by completed WBML assertions/evidence in this baseline.
- **OBSERVED** — empirically seen but version-, world-, hardware- or implementation-bound.
- **FAILED ASSUMPTION** — a hypothesis or test criterion falsified by evidence; keep it as negative knowledge.
- **UNSAFE** — do not use as a generic modding pattern without an explicit disposable/sandboxed context.
- **UNKNOWN** — deliberately unresolved; do not guess.

   Evidence: `0.0.23`

   Evidence: `0.0.28-fix1`
7. **`pw-harmony-owner`** — The tested PW startWar Harmony owner id was fluttershy.politicalworld.politics.v1392.  
   Evidence: `0.0.28/0.0.30`
8. **`save-load-signatures`** — saveToCurrentPath() and loadWorld() no-args signatures are version-bound implementation observations, not guaranteed public API.  
   Evidence: `0.0.29`
9. **`tile-reuse-implementation`** — WorldTile/array/service/manager reuse across lifecycle transitions is an implementation behavior observed on WorldBox 0.51.2.  
   Evidence: `0.0.24–0.0.30`

## FAILED ASSUMPTIONS (6)

1. **`require-tile-ref-replacement`** — Rejected: worldgen completion must not require the first WorldTile reference to change.  
   Evidence: `0.0.24-fix2–fix5`
2. **`require-old-tile-removal`** — Rejected: an old WorldTile must not be required to disappear from the current map after same-size worldgen.  
   Evidence: `0.0.24`
3. **`exact-height-reload-proof`** — Rejected: exact restoration of WorldTile.Height must not be the sole proof of reload.  
   Evidence: `0.0.29`
4. **`raw-assembly-count-stability`** — Rejected: total AppDomain assembly count must not be required to remain constant across reflection inspection.  
   Evidence: `0.0.28`
5. **`scene-owned-coroutine-survival`** — Rejected: a coroutine hosted on a world-owned object cannot be assumed to survive full world replacement.  
   Evidence: `0.0.24-fix1`
6. **`worldloaded-callback-authority`** — Rejected: on_world_loaded callback alone is not an authoritative generateNewMap completion condition in this runtime.  
   Evidence: `0.0.24-fix5/fix6`
## UNSAFE (4)

1. **`full-map-scan-per-frame`** — Unsafe/performance-hostile: scanning all 65,536 tiles in every wait-loop frame caused severe FPS degradation.  
   Evidence: `0.0.24 original`
2. **`guess-save-load-args`** — Unsafe: never guess required SaveManager/load/save arguments or paths; only invoke proven safe signatures.  
   Evidence: `0.0.29+`
3. **`destructive-tests-production-world`** — Unsafe: worldgen/save-reload/destruction suites must use disposable worlds.  
   Evidence: `0.0.20/0.0.24/0.0.29/0.0.30`
4. **`plain-null-unity-liveness`** — Unsafe pattern: plain object/null assumptions are insufficient for UnityEngine.Object liveness because fake-null semantics exist.  
   Evidence: `0.0.15`

## Baseline rules going forward

- Do **not** rerun closed suites merely to reconfirm them.
- Rerun or diff only when the WorldBox/NML/PW baseline changes, or when a narrow unresolved question requires it.
- Preserve `OBSERVED` for implementation details that are not contracts.
- Prefer `SKIP`/`UNKNOWN` over invented failures when prerequisites are absent.
- WorldTile identity replacement is never a lifecycle-completion requirement.
- Heavy full-map scans belong after lifecycle completion and should yield in chunks; never put them in per-frame wait polling.
